deepseek-v4-compliance-service - Work Plan

TL;DR (For humans)

What you’ll get: 미국 뉴욕에서 AI로 채용 심사를 하는 회사가 법적으로 매년 제출해야 하는 “편향감사 보고서”를 만들어 파는 온라인 서비스(ComplyLens). 고객이 채용 데이터를 올리면 시스템이 통계 계산과 보고서 작성을 자동으로 처리해 72시간 안에 납품하고, 1건당 $1,500를 받습니다. 이후 일리노이·캘리포니아 규제로 확장합니다.

Why this approach: 8개 축 리서치(63개 검증 클레임) 결과, “AI 사용료가 싸다”는 그 자체로는 사업 경쟁력이 되지 않습니다. 진짜 돈이 되는 건 법이 특정 서류를 강제하는 영역 — 고객이 스스로 찾아오고, 반복 구매가 생기고, DeepSeek의 1M 컨텍스트+초저가가 실제로 유리합니다. 통계는 전부 코드로 계산하고 AI는 문서 작성만 담당해 환각 위험을 원천 차단합니다.

What it will NOT do: 한국어 서비스(개인정보법상 중국 서버 사용 불가 + 한국어 품질 미검증), 고객 채용 데이터를 중국 서버로 전송(미국 호스팅만), AI가 숫자를 계산하는 일(전부 검증된 코드), 자체 GPU 서버 구축(비용 비경제).

Effort: XL — 웨이브 3개, 구현 9개 + 최종검증 4개 태스크 Risk: Medium-High — 미국 규제 시장 진입 + 법적 독립성 요건이 최대 리스크 Decisions I made for you: 후보 B(편향감사)를 v1으로 채택하고 다중관할(A)을 확장 경로로 연결; 가격 $1,500(시장 하단) 시작; 영어권 글로벌 타깃; DeepSeek+OpenRouter 멀티라우팅(단일 벤더 의존 금지); LLM은 문서화 전용(수치 생성 금지).

Your next move: 실행 시작 (사용자가 이미 “니가 다 해야돼”로 승인·위임함).

TL;DR (machine): XL effort, Medium-High risk — LL144 편향감사 서비스 v1 (통계 엔진 + DeepSeek 문서화 + 멀티라우팅 + Stripe + 랜딩) 3웨이브 9태스크.

Scope

Must have

  • NYC LL144/AEDT 편향감사 서비스 v1: ATS/CSV 데이터 업로드 → 통계 계산(selection rate, impact ratio, four-fifths rule, median-threshold scoring) → LL144 공개 요약 + 상세 보고서 납품
  • 통계는 전부 결정적 코드(pandas/numpy)로 계산 — LLM은 데이터 스키마 파싱 보조·보고서 내러티브·공개 요약 문구 생성만 담당 (C55: 감사는 EEOC 통계 프레임워크)
  • LLM 게이트웨이: OpenAI-호환 인터페이스, DeepSeek V4-Flash + OpenRouter(DeepInfra/DigitalOcean) 멀티라우팅, 규제 데이터(고객 채용 데이터)는 비-PRC 호스트로만 (C71, C75)
  • 환각 게이트: 모든 수치는 통계 엔진에서 JSON 주입, LLM 자유 생성 금지 (C35: 환각 최악 수준)
  • 결제(Stripe) + 주문 관리 + 랜딩 페이지 + SEO (규제 키워드)
  • 독립 감사인 서명 워크플로 (법적 요건 — 외부 파트너 검토 단계)
  • IL HB 3773 다중관할 확장 템플릿 준비 (C31)

Must NOT have (guardrails, anti-slop, scope boundaries)

  • 한국어 사용자 대상 서비스/한국어 UI (C65~C69 구조적 NO-GO — PIPA 중국 이전, 한국어 품질 미검증)
  • DeepSeek 직접 API 단독 의존 (C75) — 단일 벤더로 규제 데이터 전송 금지
  • 자체 GPU 호스팅 (C73: 수십억 토큰/월 이전엔 비경제)
  • ATS 본체 경쟁, 코드리뷰 도구, 번역/교육/콘텐츠 (이전 세션 거부 항목)
  • LLM이 통계 수치를 생성/수정하는 경로 (C35, C55)
  • 한국어/중국어 문서 산출물 (v1은 영어만)

Verification strategy

Zero human intervention - all verification is agent-executed. - Test decision: TDD — pytest + hypothesis (통계 엔진: Known-answer 테스트, 합성 데이터로 four-fifths rule 교차 검증), httpx 기반 API 테스트, Playwright로 결제/업로드 흐름 E2E - Evidence: .omo/evidence/ulw///a (ulw-loop 외부 실행 시 .omo/evidence/) - 통계 정확성 검증: NIST/EEOC 알려진 사례 + 합성 데이터셋(보호집단별 선택률 차이 주입)으로 기대값 대조 — 숫자 오류는 서비스 존폐 문제 (Precision demand: high) - LLM 출력 검증: 스냅샷 테스트로 템플릿 구조 고정, 수치 주입 값이 JSON 소스와 100% 일치하는지 어서션
